# Breadcrumbs v0.4.0

Tlock is now **Breadcrumbs**: a terminal focus companion for developers.
Plan a block, follow your attention across apps and browser tabs, and review
what you finished. Your history stays in SQLite on your computer.

## In this release

- A 12-page onboarding tour on first launch, with Back/Next, keyboard
  navigation, scrolling, and Skip. Replay it with `?` while ready or paused.
  Recovery takes priority; reading the tour never enables activity capture.
- A rewritten README with task-based feature explanations, examples, settings,
  and shortcuts, plus a [hands-on onboarding guide](https://github.com/SaroashDS/Breadcrumbs/blob/main/docs/ONBOARDING.md).
- Git-style focus branches with departures, returns, timestamps, app colors,
  bundled logos, and In scope / Supporting / Deviation annotations.
- A compact animated trail beside intentions and a live context status bar.
- Scope selection before starting a block, scope reuse, and an untracked option.
- Exact URL/domain rules and supported Claude Code/Codex terminal markers.
- Chrome/Edge extension with local pairing, automatic current-session pickup,
  TUI themes, and Start/Pause/Resume/confirmed Finish controls.
- Browser connection setup in Config, independent of scope selection.
- Recovery preserves the session's scope and separates running spans from
  time while Breadcrumbs was closed.
- Named checkpoints, intentions, task carryover, reflections, local export,
  sound previews, optional reading cards, and the optional companion remain.

## How to try the new features

1. Launch `breadcrumbs`, read or skip the feature tour, and press `E` to write
   one task. `Ctrl+B` adds a task; `F2` ticks it off; `Escape` leaves the editor.
2. Choose a short custom block and press `Space`. Choose scope, reuse scope,
   or start without tracking. `Space` pauses/resumes; `Q` saves and quits.
3. With app scope enabled, switch apps and return. Click the small trail or
   press `B` to inspect visits. `A`, `S`, and `V` label In scope, Supporting,
   and Deviation. Unknown/Away/Excluded keep their observation labels.
4. Open **C → Browser connection**, load the unpacked Chrome/Edge extension,
   and pair it. Choose an exact page or a domain in scope. Return to the page
   to rejoin scope; different query parameters remain different identities.
5. Open the extension popup to see an existing session. Try Pause/Resume;
   Finish asks for confirmation. Stop sharing independently of timer controls.
6. Open a supported Claude Code/Codex CLI and choose it in scope to try
   verified terminal markers. Unsupported hosts report Unknown.
7. Finish a block, save a reflection and optional rating, then review with
   `H`. Try themes, sound previews, reading cards, and the companion in `C`.

## Fixes and behavior changes

- Scope edits, including edits while paused, survive session recovery.
  Activity before/after pause and restart uses separate durable running spans.
- Late collector results from an old span or scope are discarded.
- Long-break progress advances only for full Focus countdowns, and resets
  after a full long break. Custom and early-finished work still count in totals.
- Older visits explain verification using their span's saved scope. Switching
  to an empty block clears the previous visit's details and logo.
- Old browser replies cannot overwrite newer timer state. Tab-query failures
  do not erase a healthy timer. Slow status response bodies have a timeout.
- Stale controls, duplicate Finish clicks, pre-restart revisions, and changed
  session identities cannot silently finish a different block.
- Unverified browser fallback discards plaintext window titles. Extension
  private/internal-tab exclusions and optional title capture remain explicit.
- Origin checks reject hostile web origins even with a valid token. IPv6
  domain literals are normalized without accepting a URL as a domain field.

## Reliability and privacy

Unknown browser/agent context is shown as Unknown, not a false deviation.
Timer status is independent of tab capture. Stalled response bodies, late
request results, duplicate commands, and stale session controls are covered by
regression tests. Unverified browser window titles are discarded.

QA includes the Python suite, extension worker/UI tests, isolated HTTP race and
origin tests, Windows installer/reinstall checks, legacy-data recovery, and a
real Chromium-to-TUI integration run. See [QA results](https://github.com/SaroashDS/Breadcrumbs/blob/main/docs/QA-v0.4.0.md) in the
repository and the release commit's Actions runs.

Activity export is explicit: `breadcrumbs export --activity --output activity.json`
includes observations, labels, scope, and running spans. Normal export omits
activity. URL hashes are identities, not a promise of anonymity.

## Install or upgrade

Close the old app, then run:

```powershell
irm https://raw.githubusercontent.com/SaroashDS/Breadcrumbs/main/bootstrap.ps1 | iex
breadcrumbs
```

`tlock` remains a compatibility command. Existing data in `~/.tlock` is reused
in place; saved names and sessions remain valid. New installs use
`~/.breadcrumbs`. `BREADCRUMBS_HOME` is the new data override; legacy overrides
remain supported.

The extension folder changed. Remove the old unpacked extension, run
`breadcrumbs browser path`, load that folder in Chrome/Edge, and pair it from
**Config → Browser connection**.

Native app capture supports Windows and Linux/X11. Wayland/macOS native app
capture and arbitrary editor-integrated terminal attribution remain limitations.
The timer works without activity capture.
