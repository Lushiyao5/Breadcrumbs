# Breadcrumbs v0.4.2

## Fix the loaded extension, not just the app

Live diagnosis found Chrome still registered to extension **0.2.0** in the old
Tlock runtime, while the current Breadcrumbs runtime contained **0.4.1**.
That older worker still used a ten-second heartbeat. It could report some tabs
while missing newer reporting fixes, leaving alternating verified/Unknown visits.

This release refreshes known old unpacked-extension folders during installation
and installed app startup, preserving the extension's directory identity and
pairing storage. It does not edit Chrome preferences or browser data. Newer
extension copies are not downgraded. Explicit repair is also available:

```powershell
breadcrumbs browser repair
```

**Reload the extension in chrome://extensions or edge://extensions after
updating.** The popup now displays app/extension versions, reports the loaded
version to the app, and offers a clear reload message when versions differ.
Config also identifies old reports. New Unknown records retain the diagnostic
message that explains the missing verification; old records are not relabeled.

## Activity details belong beside the trail

- Click a visit or press Enter to expand a scrollable sidebar, keeping the
  branch list visible.
- Escape collapses it; Ctrl+Enter opens the separate full detail screen.
- The branch card is smaller and bounded on large screens, with compact
  details at 80×24.
- Artwork attribution no longer appears in activity details. Credits remain
  in the bundled notices and documentation.

Update with `breadcrumbs update`, wait for `breadcrumbs update --status`,
then reopen Breadcrumbs and reload its unpacked extension. Sessions/history
remain in place. Closing other TUI instances prevents bridge-port conflicts.

QA covers old-folder refresh/idempotence, no downgrade or unrelated-folder
replacement, version diagnostics, persisted reasons, clean detail text,
sidebar/full-view interaction, the full regression suites, and real isolated
Chromium integration. Physical desktop/browser-profile edge cases can still
produce Unknown when a foreground page cannot be verified.
